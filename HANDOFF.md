## Проект и цель
Гомоку: 5 в ряд, свободный стиль (5+ считается победой), бесконечное поле.
Windows-версия — отладочная. Конечная цель: Android APK с той же логикой,
похожим интерфейсом, ~12 уровней сложности, подсказки и надпись
«моя победа не позже N ходов». Уровни/подсказки пока НЕ делать, только задел.

Порядок работ, решённый владельцем: СКОРОСТЬ → СИЛА → ИНТЕРФЕЙС → Android.

## Протокол работы (соблюдать строго)
1. Один рабочий блок = «ШАГ N», номер в заголовке. Номера не переиспользовать.
2. Владелец — не программист. Правки давать с точными якорями:
   «найдите эти строки… замените на эти», либо замена функции целиком
   с указанием границ («от def X до def Y, последнюю не удалять»).
   Отступы показывать явно.
3. В конце каждого шага: команда прогона тестов + ожидаемое PASS/FAIL,
   затем git add / commit / push с осмысленным сообщением.
4. Обновления status.md давать ЗАМЕНОЙ БЛОКА ЦЕЛИКОМ. Иначе плодятся
   дублирующиеся номера пунктов (это уже случалось трижды).
5. После шага владелец присылает «Итого: PASS=… FAIL=…» и замеры.
   Проверять по GitHub (raw или .patch), а не только на слово, если есть доступ.
6. Раннер чистит все кэши перед каждым тестом (_clear_all_caches).
   Любой новый кэш обязан быть добавлен в эту функцию.

## Уроки измерений (не наступать повторно)
1. Прибор может мерить не то. На шаге 22 bench2 показал +19%, а на деле мерил
   попадания в кэш вместо работы. Лечение: сбрасывать кэш перед замером.
2. Одиночные прогоны в разных сеансах сравнивать нельзя: дрейф машины до ±20%.
3. Первый прогон bench2 — прогрев/охлаждение. Брать второй.
4. Варианты сравнивать чередованием ВНУТРИ одного процесса при одинаковой работе.
5. Мелкий срез (400 узлов, пустая TT) не отражает реальный поиск (8000 узлов, общая TT).
6. Если шум сравним с эффектом — считать саму работу счётчиками, а не только время.
7. Кэш не должен менять результаты: всегда проверять совпадение оценок при ON/OFF.
8. Бюджет узлов — потолок, а не факт: на 36 камнях поиск досчитался раньше 6000
   узлов, и «полный» прогон повторил работу quick. Фактический объём работы
   смотреть по счётчикам (STATS), а не по заданному бюджету.
