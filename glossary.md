# Глоссарий проекта Gomoku
Простые объяснения терминов из разбора. Читать не подряд, а по необходимости.

## Игра и угрозы
- **Гомоку (пять в ряд)** — собери пять своих знаков подряд. У нас «свободный стиль»:
  ряд из 5 и больше = победа, запрещённых ходов нет.
- **Пятёрка (five)** — пять подряд, победа.
- **Четвёрка (four)** — четыре камня в окне из пяти, не хватает одного.
  Противник обязан закрыть, иначе проиграет.
- **Закрытая четвёрка** — достроить можно только с одной стороны: OXXXX.
- **Разрывная четвёрка** — четыре камня с дыркой внутри: XX.XX. Достраивается в дырку.
- **Живая четвёрка (live_four)** — открыта с двух сторон: .XXXX.
  Одним ходом не блокируется → почти победа.
- **Живая тройка (live_three)** — тройка, которая одним ходом становится ЖИВОЙ четвёркой.
  Опасна, противник обязан реагировать.
- **Спящая тройка (sleeping_three)** — становится только закрытой четвёркой. Слабее.
- **Мёртвая тройка** — зажата, не станет даже четвёркой. Ничего не стоит.
- **Точка достройки** — пустая клетка, ход в которую собирает пятёрку.
  Она же точка блокировки для противника.
- **Ключевая точка тройки** — клетка, куда надо поставить, чтобы тройка стала живой четвёркой.
- **Вилка (двойная угроза)** — две угрозы сразу: противник закрывает одну, вторая выигрывает.
  Бывает 4-4, 4-3, 3-3.
- **Ложная вилка** — у двух угроз общая ключевая клетка, один ход гасит обе.
  У нас это ловит функция `_fork_survives`.
- **Темп** — «чей сейчас ход». Угроза опаснее, если ходить вам: вы реализуете её первым.
- **Форсированный выигрыш** — выигрыш при ЛЮБОЙ защите, потому что все ответы вынуждены.
- **VCF** (Victory by Continuous Fours) — выигрыш непрерывными четвёрками.
  Каждый ход требует ответа, противник не успевает контратаковать.
- **VCT** (Victory by Continuous Threats) — то же, но разрешены ещё и живые тройки.
  Ответы менее вынуждены, искать сложнее.
- **Парирование** — ответ защитника, гасящий угрозу.
- **Контр-четвёрка** — защитник вместо блокировки делает свою четвёрку и «отбирает ход».
  Иногда это опровергает атаку.
- **Режим сопротивления** — позиция проиграна тактически; ИИ перестаёт блокировать
  и наращивает свои угрозы (`choose_resistance_move`).

## Как программа видит доску
- **Окно из 5** — пять клеток подряд. Любая угроза гомоку живёт внутри такого окна.
  На этом построен весь наш анализатор.
- **Линия** — ряд клеток одного направления: горизонталь, вертикаль, две диагонали.
- **Инвариант линии** — число, одинаковое у всех клеток одной линии
  (для диагонали ↘ это x−y). Позволяет собрать камни линии в словарь.
- **Сегмент** — кусок линии без камней противника. Дальше его границ угрозы невозможны.
- **Анализатор** — файл `gomoku_analysis.py`: превращает доску в список угроз.
- **Угроза (Threat)** — запись: тип, игрок, направление, камни, точки.
- **Кандидаты** — пустые клетки, которые имеет смысл рассматривать.
  Сейчас это всё в радиусе 2 от камней — много лишних.
- **Снапшот** — копия доски (`Board.copy`), чтобы поиск не трогал доску, которую рисует интерфейс.
- **Хеш Зобриста** — число-«отпечаток» позиции: одинаковые позиции → одинаковое число.
  Нужно для кэша.
- **Кэш** — «запомнил результат и не считаю заново».
- **Инкрементальный пересчёт** — пересчитывать только изменившееся
  (при ходе меняются ровно 4 линии), а не всю доску. Главное ускорение в плане.

## Поиск
- **Дерево перебора** — «я так, он так, я так…».
- **Узел** — одна рассмотренная позиция. Скорость движка меряют в узлах в секунду.
- **Полуход / глубина** — один ход одной стороны. Глубина 4 = по 2 хода каждому.
- **minimax** — правило выбора: свой ход — максимум оценки, чужой — минимум.
- **Alpha-beta (альфа-бета)** — отсечение заведомо бесполезных веток: если вариант хуже
  уже найденного, дальше его не смотрим. Результат тот же, работы меньше.
- **Бюджет узлов** — остановка после N рассмотренных позиций.
- **Дедлайн** — остановка по времени. Сейчас проверяется слишком редко (баг S6).
- **Iterative deepening (итеративное углубление)** — сначала смотрим на 1 ход, потом на 2, 3…
  Кончилось время — берём результат последней завершённой глубины.
- **TT (таблица транспозиций)** — кэш посчитанных позиций: одну позицию можно получить
  разным порядком ходов, зачем считать дважды.
- **EXACT / LOWER / UPPER** — пометка в TT: точное значение / «не меньше чем» / «не больше чем».
- **Сортировка ходов** — сначала смотреть самые обещающие; тогда альфа-бета отсекает больше.
- **Killer / history** — запоминание ходов, которые уже опровергали ветку, чтобы пробовать их раньше.
- **PVS** — вариант альфа-беты: первый ход проверяем полностью, остальные — дешёвой проверкой.
- **Горизонт-эффект** — беда: движок остановился на глубине 4 и «не видит»,
  что на 5-м ходу проигрывает.
- **Quiescence / продления** — не останавливаться в острой позиции, пока идут вынужденные ответы.
- **PNS (proof-number search)** — алгоритм, специально доказывающий форсированный выигрыш.
  Для гомоку подходит лучше альфа-беты.
- **PV (главная линия)** — последовательность ходов, которую движок считает лучшей.
  Нужна для подсказок и надписи «победа не позже N ходов».
- **Доказанный выигрыш** — проверен при всех ответах противника, а не «оценка большая».
- **UNKNOWN** — «не знаю, не успел посчитать». Сейчас программа путает это
  с «выигрыша нет» (баг C3).
- **Верификатор / оракул** — отдельная простая (пусть медленная) программа,
  перепроверяющая вывод основного движка.

## Оценка позиции
- **Оценка (eval)** — число «кому лучше». Плюс — лучше одной стороне, минус — другой.
- **Эвристика** — правило «на глаз», не доказательство.
- **Антисимметрия** — поменяли стороны местами → оценка меняет знак.
  Признак того, что у оценки нет перекоса.
- **BASE / TEMPO** — таблицы «сколько очков стоит угроза» и «сколько добавить, если ход наш».
- **Потенциал окна** — мелкие очки за 1–2–3 камня в свободном окне: ещё не угроза, но зародыш.
- **Связность** — сколько своих камней стоят рядом.
- **Двойной учёт** — одна угроза посчитана дважды, позиция кажется лучше, чем есть (баг C2).
- **Тюнинг весов** — подбор чисел в оценке не руками, а по результатам тысяч партий.
- **Self-play / арена** — движок играет сам с собой: версия A против версии B.
- **Elo** — рейтинг силы. Разница 100 Elo ≈ 64% очков у сильнейшего.
- **SPRT** — статистический способ решить «стало точно лучше или это шум»,
  не дожидаясь тысяч партий.

## Интерфейс
- **Canvas** — «холст» Tkinter, на котором рисуем линии и камни.
- **Элемент (item)** — одна нарисованная вещь на холсте.
  Создать/удалить — дорого, передвинуть — дёшево. Отсюда все тормоза.
- **Тег** — метка группы элементов («dyn», «bg»), чтобы двигать или удалять их разом.
- **Immediate mode** — «стереть всё и нарисовать заново» каждый раз. Просто, но медленно.
- **Retained mode** — объекты живут на холсте, мы только меняем координаты.
  Быстро; цель сессии 4.
- **Пул объектов** — запас заранее созданных элементов: прячем/показываем вместо создания новых.
- **Спрайт** — заранее нарисованная картинка (крестик, нолик), ставится одним элементом.
- **Тайл** — маленький кусочек сетки, размноженный по полю как плитка.
- **Слой** — группа элементов одного назначения: фон, сетка, камни, подсветка.
- **Dirty flag («грязный»)** — пометка «надо перерисовать».
- **Кадр / FPS / мс на кадр** — 60 FPS = 16 мс на кадр. Рисуем дольше — видны рывки.
- **Hover** — подсветка клетки под мышью. На Android его нет, там нужен другой UX.
- **Панорама / зум** — перетаскивание поля / изменение масштаба.
- **DPI / масштаб** — плотность пикселей экрана. Без учёта на телефоне всё будет мелким.
- **GIL** — «замок» Python: одновременно исполняется только один поток Python-кода.
  Поэтому поиск в потоке тормозит интерфейс.
- **Поток / процесс** — поток делит память и GIL; процесс отдельный и не мешает,
  но на Android сложнее.
- **Очередь (queue)** — безопасный способ передать результат из фонового поиска в интерфейс.
- **Anytime / кооперативный поиск** — поиск, который можно прервать в любой момент
  и который сам отдаёт управление каждые несколько миллисекунд.
  Решает сразу и тормоза, и отмену.

## Python и инструменты
- **Функция / метод / класс** — функция внутри класса называется методом.
  Класс — «тип объекта»: у нас `Board`, `GomokuApp`.
- **Сигнатура** — строка `def имя(параметры):`.
- **Отступы** — в Python задают структуру: метод внутри класса — 4 пробела, его тело — 8.
- **Обёртка (wrapper)** — маленькая функция вокруг большой, добавляющая поведение
  (у нас — лимит времени вокруг `get_best_move`).
- **global** — «меняю переменную уровня модуля, а не создаю новую локальную».
- **Исключение** — сигнал особой ситуации. `raise SearchTimeout` = «время вышло,
  разматываем поиск наверх».
- **try / finally** — «что бы ни случилось, выполни это в конце»
  (у нас — восстановить доску и снять дедлайн).
- **Рекурсия** — функция вызывает саму себя (так устроен перебор ходов).
- **dataclass** — короткая запись «класс-контейнер с полями» (наш `Threat`).
- **Подсказки типов (Optional, Tuple, Set)** — пометки для проверяльщика, на работу не влияют.
- **Декоратор** — обёртка вокруг функции; у нас `@case(...)` регистрирует тест.
- **ruff / mypy** — быстрые проверяльщики: опечатки, мёртвый код, несогласованные типы.
- **pytest / xfail** — система запуска тестов; xfail = «известный баг, ожидаемо падает».
- **Регрессия** — было хорошо, стало плохо после правки.
- **Baseline** — зафиксированный результат «до», с которым сравниваем.
- **CI** — автоматический прогон тестов при каждом коммите.
- **Коммит / откат / тег** — снимок проекта в git / возврат к снимку / имя снимка.

## Android
- **APK** — установочный файл Android-приложения.
- **Tkinter на Android не работает** — поэтому текущий интерфейс не переносится,
  а движок переносится без изменений.
- **Kivy + buildozer / python-for-android** — Python-интерфейс, собираемый в APK.
  Один код интерфейса на Windows и Android.
- **Chaquopy** — плагин, позволяющий вызывать Python-код из нативного Android-приложения.
- **Compose** — современный способ рисовать интерфейс в Android (язык Kotlin).
- **FFI / JNI** — «мост» между языками, например Python ↔ C++.
- **dp / sp** — единицы размера на Android, учитывающие плотность экрана.
